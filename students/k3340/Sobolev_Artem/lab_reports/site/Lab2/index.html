    Отчет по лабораторной работе №2. Потоки. Процессы. Асинхронность.

    Цели

    Понять отличия потоками и процессами и понять, что такое ассинхронность в Python.

    Задание

    1. Написать три различных программы на Python, использующие каждый из подходов: threading, multiprocessing и async. Каждая программа должна решать считать сумму всех чисел от 1 до 10000000000000. Разделить вычисления на несколько параллельных задач для ускорения выполнения.
    2. Написать программу на Python для параллельного парсинга нескольких веб-страниц с сохранением данных в базу данных с использованием подходов threading, multiprocessing и async. Каждая программа должна парсить информацию с нескольких веб-сайтов, сохранять их в базу данных.

    Реализация

    Задача 1

    Поскольку прямой цикл от 1 до 10 000 000 000 000 будет выполняться очень долго, сумма будет считаться по формуле (start + end) * (end - start + 1) // 2, где: - start - начальное число - end - конечное число

    Данные числа равномерно распределяются для потоков/процесс/задач

    Threading

    Создаётся количество потоков, равным количеству ядер в системе. Для каждого потока вычисляется начальное и конечное значение, по которым вычисляется сумма. В конце вычисляется сумма, полученная со всех потоков

    Результаты: - Количество потоков: 20 - Результат: 50000000000005000000000000 - Время выполнения: 0.004784 секунд

    Async

    Аналогичным образом, как в Threading, но вместо потоков, создаются задачи, которые в асинхронном режиме вычисляются и отдают результат, когда он будет готов

    Результаты: - Количество задач: 20 - Результат: 50000000000005000000000000 - Время выполнения: 0.000247 секунд

    Multiprocessing

    Создаются отдельные процессы, которые считают свою сумму и возвращают результат

    Результаты: - Количество процессов: 20 - Результат: 50000000000005000000000000 - Время выполнения: 0.345781 секунд

    Итоговая таблица результатов

    Подход Количество исполнителей Результат Время выполнения, секунд
    Threading 20 потоков 50000000000005000000000000 0.004784
    Asyncio 20 задач 50000000000005000000000000 0.000247
    Multiprocessing 20 процессов 50000000000005000000000000 0.345781

    Вывод

    Все три подхода корректно посчитали одинаковую сумму чисел от 1 до 10 000 000 000 000.

    В данной реализации вычисление выполняется очень быстро, потому что используется формула суммы арифметической прогрессии, а не прямой перебор всех чисел. Поэтому результаты времени выполнения отражают накладные расходы выбранного подхода: создание потоков, создание процессов или запуск асинхронных задач.

    Для CPU-bound задач в Python обычно лучше подходит multiprocessing, так как процессы могут выполняться параллельно на разных ядрах процессора. Однако в данном конкретном примере вычисление слишком простое, поэтому накладные расходы на создание процессов оказались больше, чем само вычисление.

    Задача 2

    В ЛР1 был реализован вариант BookCrossing, были выбраны следующие таблицы для сохранения результатов парсинга: - books - genres

    Таблица books содержит следующие столбцы: - id - title - description - genre_id - created_at - updated_at

    Таблица genres содержит следующие столбцы: - id - title - description - slug - created_at - updated_at

    Парсинг производился с сайта books.toscrape

    Общая логика вынесена в common.py: хранится список URL, выполняется загрузка HTML и парсинг страницы книги. Из страницы извлекаются название книги, описание и жанр, после чего данные сохраняются в PostgreSQL из ЛР1.

    Async

    Асинхронная реализация подходит для I/O-bound задач, так как основное время тратится на ожидание ответа от сайта и запись в базу данных. Для загрузки страниц используется aiohttp, а для работы с PostgreSQL - asyncpg.

    Все URL обрабатываются как отдельные асинхронные задачи. Сначала страница загружается, затем из HTML извлекаются название книги, описание и жанр, после чего данные сохраняются в таблицы genres и books через пул соединений.

    Результаты: - Задачи: 10 - Ссылки: 10 - Время: 1.0882 секунды

    Multiprocessing

    В данной реализации используется пул из 4 процессов. Каждый процесс независимо получает URL, загружает страницу, парсит данные и сохраняет результат в базу данных через собственное подключение.

    Такой подход позволяет выполнять задачи действительно параллельно на уровне процессов, но требует больше системных ресурсов. Для парсинга веб-страниц это не всегда эффективно, потому что основная задержка связана не с вычислениями, а с ожиданием сети и базы данных.

    Результаты: - Процессы: 4 - Ссылки: 10 - Время: 4.0184 секунды

    Threading

    В многопоточной версии список ссылок делится между 4 потоками. Каждый поток последовательно обрабатывает свою часть URL: загружает HTML, извлекает данные книги и сохраняет их в базу данных.

    Для корректного вывода сообщений в консоль используется Lock, чтобы потоки не смешивали строки между собой. Для каждой операции сохранения создаётся отдельное подключение к PostgreSQL, что упрощает работу с потоками и снижает риск конфликтов.

    Результаты: - Потоки: 4 - Ссылки: 10 - Время: 3.5095 секунды

    Итоговая таблица результатов

    Подход Количество исполнителей Ссылки Время выполнения, секунды
    Async 10 задач 10 1.0882
    Threading 4 потока 10 3.5095
    Multiprocessing 4 процесса 10 4.0184

    Вывод

    Во всех трёх реализациях программа выполняет одну и ту же последовательность действий: получает HTML страницы книги, извлекает название, описание и жанр, а затем сохраняет данные в PostgreSQL. Разница заключается в способе организации параллельного выполнения.

    Лучший результат в этой задаче показал async, потому что парсинг веб-страниц и запись в базу данных являются I/O-bound операциями, где большая часть времени уходит на ожидание внешних ресурсов. threading тоже позволяет ускорить обработку по сравнению с последовательным вариантом, но уступает асинхронному подходу. multiprocessing оказался самым медленным из-за больших накладных расходов на создание и управление процессами, что для сетевого парсинга не даёт преимущества.
